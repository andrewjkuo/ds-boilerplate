# Architecture Decision Records

Use ADRs for durable architectural, product, modelling, data, and workflow decisions.

Do not keep a parallel decisions log. If a decision matters after the current session, write an ADR.

## Template

Create ADRs as numbered markdown files, for example `0001-use-github-issues-for-backlog.md`.

```markdown
# ADR-0001: Decision Title

Date: YYYY-MM-DD

## Status

Accepted

## Context

What forces, constraints, and tradeoffs led to this decision?

## Decision

What did we decide?

## Consequences

What becomes easier, harder, required, or ruled out because of this decision?

## Alternatives Considered

- Option: reason it was not chosen.
```
